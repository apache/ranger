# Apache Ranger 2.9.0 release notes

Apache Ranger 2.9.0 was released on August 8, 2026. It is the current stable release. The release adds the Ranger PDP server, a thin-client authorization library, a Polaris plugin, action-based policy evaluation for Ozone, header-based authentication and a large number of security and dependency fixes.

## Highlights

- **Ranger PDP server** — a new `pdp` module that runs the policy engine as a standalone service and answers authorization
  requests over REST ([RANGER-5371](https://issues.apache.org/jira/browse/RANGER-5371)). A companion `authz-remote` library lets plugins integrate as thin clients ([RANGER-5550](https://issues.apache.org/jira/browse/RANGER-5550)), and
  `RangerEmbeddedAuthorizer` accepts a caller-provided audit handler ([RANGER-5505](https://issues.apache.org/jira/browse/RANGER-5505)).
- **Apache Polaris plugin** to authorize Apache Iceberg catalogs managed by Polaris ([RANGER-4910](https://issues.apache.org/jira/browse/RANGER-4910), [RANGER-5546](https://issues.apache.org/jira/browse/RANGER-5546)).
- **Ozone action-based policies** — the Ozone service definition gains an `action-matches` policy condition and matchers for
  S3-style actions, behind a feature flag ([RANGER-5628](https://issues.apache.org/jira/browse/RANGER-5628), [RANGER-5667](https://issues.apache.org/jira/browse/RANGER-5667), [RANGER-5687](https://issues.apache.org/jira/browse/RANGER-5687)).
- **Header-based authentication** for Ranger Admin ([RANGER-5499](https://issues.apache.org/jira/browse/RANGER-5499)), configuration-based super users and super groups ([RANGER-5627](https://issues.apache.org/jira/browse/RANGER-5627)), and an
  authorization check for the `doAsUser` parameter ([RANGER-5539](https://issues.apache.org/jira/browse/RANGER-5539)).
- **Tag sync for Trino** — TagSync processes Atlas notifications for Trino entities ([RANGER-5522](https://issues.apache.org/jira/browse/RANGER-5522)); Atlas Kafka consumer updated for Kafka 3.9 ([RANGER-5658](https://issues.apache.org/jira/browse/RANGER-5658)).
- **Performance** — faster policy and role create/update when many users, groups and roles exist ([RANGER-3899](https://issues.apache.org/jira/browse/RANGER-3899), [RANGER-5614](https://issues.apache.org/jira/browse/RANGER-5614)).
- **Dependency and packaging clean-up** — Tomcat 9.0.115 ([RANGER-5493](https://issues.apache.org/jira/browse/RANGER-5493)), Bouncy Castle 1.84 ([RANGER-5639](https://issues.apache.org/jira/browse/RANGER-5639)), Netty 4.1.130 ([RANGER-5502](https://issues.apache.org/jira/browse/RANGER-5502)), new
  `ranger-common-utils` module ([RANGER-5519](https://issues.apache.org/jira/browse/RANGER-5519)), removal of `jersey-bundle` and `javax.servlet-api` dependencies ([RANGER-5523](https://issues.apache.org/jira/browse/RANGER-5523), [RANGER-5515](https://issues.apache.org/jira/browse/RANGER-5515)).
- **Security fixes** — uniform TLS hostname verification across HTTP clients ([RANGER-5689](https://issues.apache.org/jira/browse/RANGER-5689)), rate limiting in the UNIX auth service ([RANGER-5690](https://issues.apache.org/jira/browse/RANGER-5690)),
  no bearer tokens in logs ([RANGER-5693](https://issues.apache.org/jira/browse/RANGER-5693)), hardened GraalJS engine for `_expression` conditions ([RANGER-5629](https://issues.apache.org/jira/browse/RANGER-5629)), Hive CTAS/temporary-table UDF
  authorization ([RANGER-5634](https://issues.apache.org/jira/browse/RANGER-5634)).
- **Tools and clients** — `apache-ranger` Python client 0.0.13 ([RANGER-5653](https://issues.apache.org/jira/browse/RANGER-5653)), Performance Analyser on Python 3.11 ([RANGER-5532](https://issues.apache.org/jira/browse/RANGER-5532)); the default
  access-audit store for a fresh install is Solr ([RANGER-5710](https://issues.apache.org/jira/browse/RANGER-5710)).
