# Apache Ranger 2.2.0 release notes

Apache Ranger 2.2.0 was released on November 1, 2021. The release introduces audit filters to reduce audit volume, Kerberos and SSL support in the client libraries, session inactivity timeout, and many UserSync, Hive and policy-engine fixes.

## Highlights

- **Audit filters** — per-service filters that decide which accesses are audited, with UI support and defaults created on
  service creation ([RANGER-3000](https://issues.apache.org/jira/browse/RANGER-3000), [RANGER-3191](https://issues.apache.org/jira/browse/RANGER-3191), [RANGER-3214](https://issues.apache.org/jira/browse/RANGER-3214), [RANGER-3228](https://issues.apache.org/jira/browse/RANGER-3228)).
- **Hive** — `SHOW ROLE GRANT` ([RANGER-2640](https://issues.apache.org/jira/browse/RANGER-2640)), URL authorization for temporary UDFs ([RANGER-3017](https://issues.apache.org/jira/browse/RANGER-3017)), fixes for role commands in Beeline sessions
  ([RANGER-3104](https://issues.apache.org/jira/browse/RANGER-3104), [RANGER-3252](https://issues.apache.org/jira/browse/RANGER-3252), [RANGER-3350](https://issues.apache.org/jira/browse/RANGER-3350)).
- **Policy engine** — ACL computation can expand roles and include chained plugins ([RANGER-3397](https://issues.apache.org/jira/browse/RANGER-3397)), read-write locks for the policy engine
  and tag repository ([RANGER-3192](https://issues.apache.org/jira/browse/RANGER-3192)), delegate-admin for specific permissions ([RANGER-3122](https://issues.apache.org/jira/browse/RANGER-3122)), more resilient incremental policy changes ([RANGER-3253](https://issues.apache.org/jira/browse/RANGER-3253)).
- **Clients** — Kerberos and SSL support in the Java client ([RANGER-2910](https://issues.apache.org/jira/browse/RANGER-2910), [RANGER-3212](https://issues.apache.org/jira/browse/RANGER-3212)) with documentation ([RANGER-3223](https://issues.apache.org/jira/browse/RANGER-3223)).
- **Admin UI and server** — session inactivity timeout ([RANGER-3363](https://issues.apache.org/jira/browse/RANGER-3363), [RANGER-3388](https://issues.apache.org/jira/browse/RANGER-3388)), audit ID shown and searchable ([RANGER-3056](https://issues.apache.org/jira/browse/RANGER-3056), [RANGER-3057](https://issues.apache.org/jira/browse/RANGER-3057)), user sync source shown
  ([RANGER-3285](https://issues.apache.org/jira/browse/RANGER-3285), [RANGER-3293](https://issues.apache.org/jira/browse/RANGER-3293)), cluster name on the service form ([RANGER-3006](https://issues.apache.org/jira/browse/RANGER-3006)), batch upload of tags ([RANGER-3309](https://issues.apache.org/jira/browse/RANGER-3309)), import policies by name/service/zone ([RANGER-3078](https://issues.apache.org/jira/browse/RANGER-3078)).
- **UserSync** — performance improvements ([RANGER-2986](https://issues.apache.org/jira/browse/RANGER-2986)), graceful handling of invalid user names ([RANGER-3207](https://issues.apache.org/jira/browse/RANGER-3207)), memory fix for 300K+ group
  mappings ([RANGER-3374](https://issues.apache.org/jira/browse/RANGER-3374)).
- **Dependencies** — Solr 8.6.3 ([RANGER-3091](https://issues.apache.org/jira/browse/RANGER-3091)), Kafka 2.5 ([RANGER-3096](https://issues.apache.org/jira/browse/RANGER-3096)), Tomcat 8.5 ([RANGER-3105](https://issues.apache.org/jira/browse/RANGER-3105)), TLS 1.2+ ([RANGER-3153](https://issues.apache.org/jira/browse/RANGER-3153)), Spring and Spring Security upgrades ([RANGER-2950](https://issues.apache.org/jira/browse/RANGER-2950)),
  Kafka client uses AdminClient instead of ZooKeeper ([RANGER-3001](https://issues.apache.org/jira/browse/RANGER-3001)).
- **Docker** — HiveServer2 with the Ranger plugin ([RANGER-3185](https://issues.apache.org/jira/browse/RANGER-3185)), cached downloads ([RANGER-3196](https://issues.apache.org/jira/browse/RANGER-3196)).
