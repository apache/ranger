# Apache Ranger 2.7.0 release notes

Apache Ranger 2.7.0 was released on July 30, 2025. The release splits the audit framework into one library per destination, modernizes the Python scripts for Python 3, and adds retry and service-configuration improvements. It contains a breaking change for plugin implementers; read the section below before you upgrade a custom plugin.

## Highlights

- **Audit module refactoring** — each audit destination now lives in its own module ([RANGER-5208](https://issues.apache.org/jira/browse/RANGER-5208)); see the breaking changes below.
- **Python 3** — installer and utility scripts modernized for Python 3 ([RANGER-5147](https://issues.apache.org/jira/browse/RANGER-5147)).
- **REST client resilience** — `RangerRESTClient` retries GET requests on HTTP 5xx errors ([RANGER-5201](https://issues.apache.org/jira/browse/RANGER-5201)).
- **Policy management** — delete multiple policies with a wildcard through the API ([RANGER-5113](https://issues.apache.org/jira/browse/RANGER-5113)); the service configuration UI shows
  additional settings such as `service.admin.users` and `service.admin.groups` ([RANGER-3643](https://issues.apache.org/jira/browse/RANGER-3643)).
- **UserSync** — `ranger.usersync.ldap.referral=follow` is the default ([RANGER-5078](https://issues.apache.org/jira/browse/RANGER-5078)).
- **Docker** — pre-built `ranger-base` image pulled from Docker Hub ([RANGER-5158](https://issues.apache.org/jira/browse/RANGER-5158), [RANGER-5241](https://issues.apache.org/jira/browse/RANGER-5241)), Ubuntu base update ([RANGER-5138](https://issues.apache.org/jira/browse/RANGER-5138)), all databases in one
  compose file with exposed ports ([RANGER-5166](https://issues.apache.org/jira/browse/RANGER-5166), [RANGER-5167](https://issues.apache.org/jira/browse/RANGER-5167)), support for the `apache/ranger-tools` repository ([RANGER-5236](https://issues.apache.org/jira/browse/RANGER-5236)).
- **Quality** — JaCoCo code-coverage report in CI ([RANGER-5229](https://issues.apache.org/jira/browse/RANGER-5229)), unit tests for the Atlas authorizer ([RANGER-5216](https://issues.apache.org/jira/browse/RANGER-5216)), Swagger UI 5.20.1 ([RANGER-5164](https://issues.apache.org/jira/browse/RANGER-5164)).
- **Notable fixes** — plugin classloader parent ([RANGER-3636](https://issues.apache.org/jira/browse/RANGER-3636)), tag allow/deny policy enforcement ([RANGER-5162](https://issues.apache.org/jira/browse/RANGER-5162), [RANGER-5202](https://issues.apache.org/jira/browse/RANGER-5202), [RANGER-5225](https://issues.apache.org/jira/browse/RANGER-5225)), HDFS audit write/append
  modes ([RANGER-5102](https://issues.apache.org/jira/browse/RANGER-5102)), row-filter expression evaluation ([RANGER-5174](https://issues.apache.org/jira/browse/RANGER-5174)), master key migration to external key stores ([RANGER-5169](https://issues.apache.org/jira/browse/RANGER-5169)).

## Breaking changes

- The library `ranger-plugins-audit` is no longer available starting with 2.7.0 (the Maven artifact of that name is
  now a parent POM without a jar). Its contents are split into one library per
  audit destination, so a plugin only needs the destinations it uses. Replace references to `ranger-plugins-audit` with:
    - `ranger-audit-dest-cloudwatch`
    - `ranger-audit-dest-es`
    - `ranger-audit-dest-hdfs`
    - `ranger-audit-dest-kafka`
    - `ranger-audit-dest-log4j`
    - `ranger-audit-dest-solr`
- Plugin packages in 2.7.0 bundle the dependent libraries for two audit destinations only: Solr and HDFS. Earlier versions
  bundled libraries for every destination (AWS CloudWatch, Elasticsearch, Kafka, Log4j). If you need another destination,
  rebuild the plugin package after adding the corresponding `ranger-audit-dest-*` dependency to the plugin's `pom.xml` and
  packaging descriptor.
